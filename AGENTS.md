## ⚠️ Important

**Never use `git push` or `git commit`.** The user will handle commits themselves. All deployments are handled by CI (GitHub Actions). Just make your changes and let the user commit and push.

## Vault setup

The campaign vault (`nicholaswagner/warforthecrown`) is no longer a submodule. It lives at `vault/`, which is gitignored. Before running `bun run sync-content` for the first time, point `vault/` at your local working copy:

```sh
ln -s ~/Repos/warforthecrown vault
```

CI clones the public repo into `vault/` automatically — see `.github/workflows/deploy.yml`.

## Bun

Default to using Bun instead of Node.js.

- Use `bun <file>` instead of `node <file>` or `ts-node <file>`
- Use `bun test` instead of `jest` or `vitest`
- Use `bun build <file.html|file.ts|file.css>` instead of `webpack` or `esbuild`
- Use `bun install` instead of `npm install` or `yarn install` or `pnpm install`
- Use `bun run <script>` instead of `npm run <script>` or `yarn run <script>` or `pnpm run <script>`
- Use `bunx <package> <command>` instead of `npx <package> <command>`
- Bun automatically loads .env, so don't use dotenv.

## APIs

- `Bun.serve()` supports WebSockets, HTTPS, and routes. Don't use `express`.
- `bun:sqlite` for SQLite. Don't use `better-sqlite3`.
- `Bun.redis` for Redis. Don't use `ioredis`.
- `Bun.sql` for Postgres. Don't use `pg` or `postgres.js`.
- `WebSocket` is built-in. Don't use `ws`.
- Prefer `Bun.file` over `node:fs`'s readFile/writeFile
- Bun.$`ls` instead of execa.

## Testing

Use `bun test` to run tests.

```ts#index.test.ts
  expect(1).toBe(1);
});
```

## Frontend — React Router 7 + Fumadocs

This project uses **React Router 7** in **SPA mode** (no SSR) with **Fumadocs** as the documentation framework, **Tailwind CSS 4**, and **Vite** for the dev server and build.

### Architecture

- **`app/`** — React Router app (root, routes, components, lib)
- **`content/`** — MDX source files for docs, split into `narrative/` and `reference/`
- **`.source/`** — Generated by `fumadocs-mdx` (source config, dynamic types, browser/server loaders)
- **`build/client/`** — Static output (deployed to GitHub Pages)
- **`vault/`** — Symlinked campaign vault (gitignored)

### Key files

| File | Purpose |
|------|---------|
| `vite.config.ts` | Vite config with Tailwind, tsconfig paths, Fumadocs MDX, and React Router plugins |
| `react-router.config.ts` | SPA mode, basename (`BASE_PATH` env), prerender routes |
| `app/root.tsx` | Root layout with Fumadocs `RootProvider`, `HomeLayout`, meta, and 404 error boundary |
| `app/routes.ts` | Route definitions — index → `docs.tsx`, catch-all → `docs.tsx`, plus API routes |
| `app/routes/docs.tsx` | Main docs page: loader fetches page from Fumadocs source, renders via `DocsLayout` + `DocsPage` |
| `.source/source.config.mjs` | Fumadocs config — defines `content/` as docs dir, extends page schema with `source` field |
| `cli.json` | Fumadocs CLI config (aliases, radix-ui, react-router framework) |

### Dev & build

```sh
# Development (HMR, Tailwind JIT, Fumadocs MDX)
bun run dev

# Production build
bun run build   # syncs vault content, generates OG images, builds, flattens basepath
```

The build sets `BASE_PATH=/wftc/` for GitHub Pages deployment (see `.github/workflows/deploy.yml`).

### Content structure

```
content/
├── meta.json              # Collection metadata
├── index.mdx              # Home page
├── narrative/             # Story content
│   ├── act-0-the-children-s-adventure/
│   ├── knightly-notes/
│   ├── act-1-crownfall/
│   └── meta.json
└── reference/             # Reference material
    ├── places/, people/, factions/, documents/, items/, events/
    ├── geography.mdx
    └── meta.json
```

Each MDX page supports a `source` frontmatter field pointing to the vault file (e.g. `vault/narrative/...md`). This enables the "Edit on GitHub" link in the UI.

### Pages & routes

All content under `content/` is auto-discovered by Fumadocs. Page URLs are derived from the file path (e.g. `content/reference/places/whitethorn/index.mdx` → `/reference/places/whitethorn`).

Static pages are prerendered in `react-router.config.ts`:
- All content pages
- `/llms.txt` and `/full.txt` (LLM-readable exports)
- `/api/search` (search endpoint)

### Custom components

- **`CampaignGraph`** — Interactive force-directed graph of the campaign world. Built from `app/lib/build-graph.ts` which walks the vault for links between pages.
- **`SearchDialog`** — Full-text search powered by `@orama/orama` (client-side).
- **`GithubInfo`** — Displays repo stats from the GitHub API.
- **`mdx.tsx`** — Custom MDX component mapping (wikilinks → `<Link>`, etc.).

### OG images

Generated via `scripts/generate-og.tsx` using `@takumi-rs/image-response`. Outputs to `public/og/`. One image per page.

### GitHub Pages deploy

CI (`.github/workflows/deploy.yml`):
1. Checks out `wftc` and `nicholaswagner/warforthecrown` (vault)
2. `bun install --frozen-lockfile`
3. `bun run build` (with `BASE_PATH=/wftc/`)
4. Uploads `build/client/` as Pages artifact

## Styling

Tailwind CSS 4 via `@tailwindcss/vite`. Styles live in `styles/app.css`. Fumadocs UI components use Radix UI primitives with Tailwind utility classes. CSS variables follow Fumadocs' `fd-*` naming convention (e.g. `fd-primary`, `fd-muted-foreground`).

## Path aliases

Configured in `tsconfig.json`:
- `@/*` → `./` (project root)
- `collections/*` → `./.source/*` (Fumadocs generated collections)

Use `@/` for imports within the app.
